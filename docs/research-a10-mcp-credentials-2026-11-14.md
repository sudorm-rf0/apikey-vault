# A10：MCP 凭据配置与轮换机会

调查日期：2026-11-14。状态：研究成果，未发布，商业参数待批准。

## 决策

优先验证「本机多个 MCP 客户端复用同一凭据时，如何发现受影响的配置并安全完成更新」；暂不开发新的通用密钥管理器或自动轮换服务。现有证据支持问题存在，但尚不支持估算需求规模、成交率或付费意愿。一个开发者的公开描述不是代表性样本。

目标用户假设：使用多个本机 MCP 客户端、维护至少 5 个依赖静态 API token 的服务的个人开发者或小团队。要解决的是配置分散与轮换后的漏更新；**不**声称隐藏密钥于已获得它的 MCP 进程，也不承诺自动创建或撤销上游凭据。

## 基线与重复工作

- `apikey-vault` 已提供本地加密 SQLite、CLI/HTTP 取钥、GUI、加密同步；当前 README 未描述 MCP 配置引用或消费关系图。`get` 会返回明文，接收进程仍可访问它。
- 同机 `agent-infrastructure` 的 `docs/adr/0002-secret-broker-aos.md` 和 `docs/status.md` 记录了现有 0600 文件及 wrapper 注入；`docs/audit/17-recovery-runbook.md` 已有手工轮换流程。因此任何原型应先验证能否复用现有 wrapper，而非平行建设第二套 broker。文档是历史记录，不证明当前环境状态。
- `ai-company-os` 的任务、项目和知识文档中未发现直接对应本机会的记录；本轮未检索私人会话或声称覆盖所有 Agent 工作。

## 建议验证包：只读消费清单

以假数据验证一款本地工具：显式指定一个测试配置目录及一份用户维护的服务到凭据名称映射，输出 `credential-name → client/server → config path → restart required/unknown`。只读配置，默认不读取值、不输出值、不上传、不修改配置或服务；未知语法标记 unknown，不把未知当作安全。配置路径和名称本身可能敏感，输出由用户保管。暂不扫描用户真实主目录，不对任意配置作泛化的可靠发现承诺。

**假设与对照**：选定一个真实客户端版本及一种格式，先用人工清单建立金标准，再比较工具的完整度和耗时；与现有 AOS wrapper 和手工流程对照。如果用户只需少量服务或已有集中网关，直接继续使用现有方案。

**验收标准**（仅针对约定格式和合成 fixture）：

1. 不调用 vault、网络或子进程；仅访问显式指定路径。可识别映射中两个客户端、三个服务的已知引用，并将不支持的格式明确标成 unknown。
2. fixture 内放入唯一假密钥哨兵：标准输出、标准错误和产物中均不得出现哨兵；不输出完整配置。拒绝符号链接越界及路径遍历，输入异常时失败且不泄露原文。
3. 轮换指引区分「本工具发现的引用」「人工确认的消费者」「未知」；要求用户在上游创建/替换凭据、按客户端实际行为重启并验证后，再自行撤销旧凭据。不执行这些操作。
4. 使用至少 3 名符合目标画像的独立开发者做经同意的访谈或走查，记录使用工具数、真实漏更新经历、手工耗时、现有方案及是否愿意继续试用；不收集密钥。若少于 2 人确认问题反复出现且愿意试用，停止投入。该阈值仅用于探索，不等于市场验证。
5. 交付前安全复核：明确同用户恶意进程、环境变量及日志暴露不在本工具防护范围；无真实密钥和外部副作用的自动化测试通过。
